# TAVRN-BLE deviation and decision register

Status: complete normative companion to `TAVRN-BLE-PoC-0.1`

Frozen: 2026-08-05

This register makes every known intentional mismatch explicit. “Accepted” means
normative for this proof of concept. “Deferred” and “out of scope” are deliberate
non-implementations, not unresolved questions.

## Closed contradiction notes

- The dirty TAVRN working tree does not alter executable behavior: it fixes
  v2.2 prose sizes/defaults and packet-header comments only. Therefore the
  behavioral source audit is pinned to clean commit `fc5f256`.
- The current source's `kMaxNewVerificationsPerCycle=4` is adopted, while its
  “verify all hard-expired entries” loop is intentionally not adopted.
- The source's `m_maxMetadataEntries=4` is the candidate-selection cap; it is
  not permission to overrun a BLE frame. Wire-v2's exact static capacities are
  adopted by `META-02`.
- E_RREP_ACK timeout and HACK retry exhaustion remain separate events. Neither
  is an alias for the other.
- Local repair is not part of TAVRN v2.2 conformance and must be reported as the
  optional TAVRN-BLE v2.3-inspired extension.
- Architecture owns fixed storage, so the profile now mirrors its one-context,
  four-DATA repair limit instead of the v2.3 proposal's three/five defaults.
- The architecture's provisional 16-bit transmitter seam was corrected under
  `DEV-018`; physical peer identity uses full AdvA, while AODV_ONLY derives SID16
  from the same AdvA and uses it as the standalone remote logical route namespace
  under `DEV-021`.

There are no unresolved normative contradictions in this register. A future
checker finding that changes behavior requires a new profile/deviation revision,
not an implementation-only exception.
